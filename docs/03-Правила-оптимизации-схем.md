# Правила оптимизации раскладки схем Archi (зафиксированы)

Этот документ — рабочий регламент. Любая оптимизация любой схемы выполняется **только**
по нему, чтобы результаты были сопоставимы между собой и воспроизводимы.

---

## 1. Цель

Снизить число пересечений связей и сделать подписи связей читаемыми, **не меняя
содержание модели** и сохранив компактность (схема помещается на один лист).

---

## 2. Что разрешено менять

| # | Разрешено |
|---|---|
| Р1 | Координаты блоков (`bounds/@x`, `@y`) — блок можно переставить в любое место |
| Р2 | Маршрут связи — добавление, изменение и удаление точек излома (`bendpoint`) |
| Р3 | Порядок блоков внутри одного родителя |
| Р4 | Размер **родительского** блока-контейнера, если это нужно, чтобы вложенные блоки поместились без наложений |

## 3. Что менять запрещено

| # | Запрещено |
|---|---|
| З1 | Добавлять, удалять, переименовывать элементы и связи |
| З2 | Менять тип связи (flow / realization / association / …) и её направление |
| З3 | Менять свойства (`Platform`, `Status`, …), документацию, вложенность |
| З4 | Выносить вложенный блок из родителя — **вложенные блоки остаются вложенными** и целиком внутри границ родителя |
| З5 | Уменьшать размер блока ниже исходного или ниже минимума из п. 4 — текст должен оставаться читаемым |
| З6 | Ломать связь, которую можно провести напрямую (см. П6) |

---

## 4. Ограничения геометрии

| Параметр | Значение |
|---|---|
| Сетка | 12 px (координаты кратны 12) |
| Максимум полотна | 1920 × 1080 px, при исходном полотне больше — не более исходного |
| Минимальная ширина блока-ИС | 120 px |
| Минимальная ширина блока-функции | 100 px |
| Минимальная высота блока | 55 px |
| Зазор между соседними блоками по горизонтали | ≥ 24 px |
| Зазор между соседними блоками по вертикали | ≥ 20 px |
| Отступ вложенного блока от границы родителя | ≥ 12 px |
| Свободный коридор для подписанной связи | ≥ 24 px |

Компактность достигается **сжатием пустот**, а не уменьшением блоков и шрифта.

---

## 5. Правила прокладки связей

| # | Правило |
|---|---|
| П5.1 | Все изломы — **строго под прямым углом**: каждый сегмент либо горизонтальный, либо вертикальный. Косых сегментов после перекладки быть не должно |
| П5.2 | **Прямые связи не ломать.** Если связь идёт напрямую, ни с чем не пересекается и не проходит сквозь посторонние блоки — оставить как есть, `bendpoint` не добавлять |
| П5.3 | Не более 4 изломов на связь. Если нужно больше — переставить блок (Р1), а не усложнять маршрут |
| П5.4 | Связь не должна проходить сквозь блок, не являющийся её источником или целью |
| П5.5 | Параллельные связи, идущие в одном коридоре, разводить с шагом 12 px, чтобы подписи не накладывались |
| П5.6 | Подпись связи размещается на самом длинном сегменте маршрута |

---

## 6. Правила размещения блоков

| # | Правило |
|---|---|
| П6.1 | Раскладка слоями по преобладающему направлению потоков: поставщики данных — слева/сверху, ядро схемы — в центре, потребители — справа/снизу |
| П6.2 | Блок с наибольшим числом связей (хаб) размещается ближе к центру полотна |
| П6.3 | Соседи хаба упорядочиваются вокруг него так, чтобы связи не перехлёстывались (порядок соседей повторяет их порядок на противоположной стороне) |
| П6.4 | Блоки, между которыми нет связей, могут располагаться как угодно — их положение используется как «люфт» для распутывания остального |
| П6.5 | Блоки легенды («Целевая ИС», «Существующая ИС», …) и `Note` выносятся в один угол и из расчёта пересечений исключаются |
| П6.6 | Актёры (`BusinessActor`) размещаются по внешнему периметру схемы |

## 7. Метрика

Считается скриптом `tools/archi_metrics.py` — единый источник чисел, «на глаз» не оцениваем.

```bash
python3 tools/archi_metrics.py "Склады/WMS.archimate" --view "Целевая архитектура"
```

| Метрика | Роль | Цель |
|---|---|---|
| **`ПЕРЕСЕЧЕНИЙ`** — число пар пересекающихся связей | **основная** | минимум |
| `сквозь_блоки` — связей, проходящих сквозь посторонний блок | вторичная | минимум |
| `ортогональных` — доля связей на ортогональной сетке | вторичная | максимум |
| `полотно` — габарит | ограничение | не расти |

Связи, выходящие из общей вершины, пересечением **не считаются** (они и так сходятся
в одной точке). Легенда и `Note` в расчёт не входят.

## 8. Итерационный процесс

Один цикл = **итерация → замер → анализ → план следующей итерации**.

1. **Замер базовой линии.** Запустить метрику на исходной схеме, записать числа.
2. **Итерация.** Внести изменения по правилам разделов 2–6. Одна итерация решает
   одну задачу (например: «развести хаб `ERP (Ядро)` и его 9 соседей»), а не всё сразу.
3. **Замер.** Повторно запустить метрику.
4. **Анализ.** Зафиксировать: было → стало, что дало эффект, какие пересечения остались
   и почему.
5. **План.** Сформулировать цель следующей итерации.

### Критерий приёмки итерации

Итерация принимается, если **одновременно**:
- `ПЕРЕСЕЧЕНИЙ` не выросло;
- `полотно` не выросло более чем на 10 % от базовой линии;
- не нарушено ни одно правило раздела 3 (запреты).

Непринятая итерация откатывается, схема возвращается к лучшей сохранённой версии.

### Условия остановки

| # | Условие | Действие |
|---|---|---|
| С1 | `ПЕРЕСЕЧЕНИЙ = 0` | стоп, показать результат |
| С2 | **За 3 итерации подряд число пересечений не снизилось** | стоп, показать лучшую версию |
| С3 | Дальнейшее снижение возможно только нарушением запретов (раздел 3) | стоп, показать результат и описать, что мешает |

Счётчик «3 итерации» сбрасывается при **любом** снижении пересечений, даже на единицу.

## 10. Сохранность исходников

- Исходный файл до оптимизации не перезаписывается «молча» — правки коммитятся отдельно,
  так что предыдущая версия всегда доступна в git.
- Оптимизируется указанная схема (View); остальные схемы модели остаются нетронутыми.
- Формат файла сохраняется: если исходник был ZIP-контейнером, результат тоже ZIP.

## 11. Порядок работы

1. Вы называете схему или схемы — в формате `Модель / View`
   (например: `Склады / Целевая архитектура`).
2. Я привожу базовые метрики и план первой итерации.
3. Выполняю итерации по разделу 8 до срабатывания условия остановки.
4. Отдаю отчёт по разделу 9 и изменённый файл.
